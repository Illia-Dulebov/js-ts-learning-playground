# Learner Context

## Developer background

- Experienced Flutter/Dart developer with approximately 4+ years of commercial experience.
- Has worked with BLoC/Cubit, Provider, GetX, Clean Architecture, REST APIs, Firebase, WebSockets, local persistence, testing, and mobile app releases.
- Has experience with real-time application behavior, reconnection handling, performance profiling, and code reviews.
- Has taken project-lead responsibilities and mentored other Flutter learners.
- Wants to grow beyond feature implementation into stronger software architecture, backend engineering, code review, and engineering judgment.

## Current gaps and goals

- Backend experience is limited compared with Flutter experience.
- Wants to learn TypeScript and backend development without being overwhelmed by a large project.
- Wants to become proficient at AI-assisted development, including agent instructions, reusable skills, context management, and token management.
- Wants to understand and review AI-generated code rather than blindly accepting it.

## Learning preferences

- Preferred approach: hybrid — structured fundamentals combined with small project-related exercises.
- Availability: approximately 2–3 hours per day.
- Prefers interactive mentoring, hints, explanations, and exercises.
- Should attempt problems independently before receiving complete solutions.
- Dart comparisons are useful, but should not hide important differences between Dart and JavaScript/TypeScript.
- Keep each session focused and manageable.

## Agreed project direction

Long-term learning project: a **Simplified Collaborative Workspace**.

The project scope must remain small initially. Do not attempt to build a full Trello/Linear clone.

Potential progression:
1. A simple task manager with in-memory data.
2. A small REST API and relational database.
3. Authentication, validation, error handling, and tests.
4. Only later, if justified, consider real-time updates, offline support, and synchronization.

Potential stack:
- Client: Flutter.
- Backend: TypeScript + NestJS.
- Database: PostgreSQL.

These are provisional learning choices, not requirements to introduce every technology immediately.

## Mentorship agreement

The learner is responsible for understanding and approving code. The assistant should help the learner reason, design, implement, test, and review.

The objective is to learn how to design and maintain software systems, not simply to finish an application.
